Objectifs du Projet

De la Donnée Brute à l'Intelligence

Conception d'un système complet intégrant des données hétérogènes pour offrir des services avancés sur les véhicules.

Pipeline Technique

Modélisation OWL → Extraction (Scraping/LLM) → Mapping RML → Validation SHACL → Exploitation GraphRAG

Modélisation Ontologique (OWL & SKOS)

Architecture "Core" Spécifique

Création d'une ontologie dédiée (sans réutiliser un vocabulaire générique existant pour le cœur) pour garantir la précision du domaine.

1. Structure OWL Riche

Hiérarchie fine : Vehicle → Car → SUV, HighPerformanceCar.
Définition formelle des propriétés : Relations transitives, symétriques et inverses.

2. Vocabulaires Contrôlés (SKOS)

Gestion des concepts via des Thésauri pour normaliser les données hétérogènes (Types de carburant, Transmissions, Classes).

Validation Structurelle Avancée

Validation de Graphe et Formes Imbriquées

Au-delà des simples vérifications de types, nous utilisons SHACL pour valider la structure du graphe et l'intégrité des relations entre entités.

Mécanismes complexes utilisés :

  • sh:node (Nested Shapes) : Validation récursive (ex: Véhicule valide si Constructeur valide).
  • sh:class & sh:minCount : Garantie de l'intégrité référentielle vers l'Ontologie.
  • Pattern Matching : Validation des formats spécifiques (Codes moteurs).

Exemple : Validation en Cascade

:VehicleIntegrityShape a sh:NodeShape ;
  sh:targetClass auto:Vehicle ;
  sh:property [
    sh:path auto:manufacturedBy ;
    sh:minCount 1 ;
    sh:class auto:Manufacturer ;
    # Validation imbriquée du noeud voisin
    sh:node [
      sh:property [
        sh:path rdfs:label ;
        sh:datatype xsd:string ;
      ]
    ]
  ] .

  • EPA (US Gov) : Specs techniques, consommation, émissions (6 552 entrées).

2. Pipeline Non-Structuré & IA

Transformation de textes bruts en données exploitables :

Phase 1 : Web Scraping
Récupération brute depuis UltimateSpecs.

Phase 2 : Extraction & NER (LLM)
Utilisation d'Ollama (Phi3) pour la Reconnaissance d'Entités Nommées : identification automatique des Marques, Modèles et Moteurs dans le texte.

Lifting sémantique avec RML

Standardisation RDF

Transformation industrielle des données via RMLMapper (Docker).

  • Règles de Mapping : Définition déclarative liant les colonnes CSV/JSON aux propriétés de notre ontologie OWL.
  • URI Strategy : Génération d'identifiants uniques et stables (ex: auto:Vehicle/Audi_Q7_2022).
  • Typage Strict : Conversion automatique des valeurs numériques (integers, doubles) pour permettre les requêtes de filtre SPARQL.

Recommandation : Link Prediction

Approche "Item-to-Item"

Nous avons développé un système de recommandation qui ne se base pas sur l'historique utilisateur, mais sur la similarité sémantique et structurelle entre les entités du graphe.

Algorithme de Similarité Pondérée

1. Marque (30%) : Forte influence.

2. Année (20%) : Proximité temporelle.

3. Performance (20%) : Cylindrée similaire.

4. Usage (15%) : Conso Ville.

5. Avis (15%) : Score utilisateur.

Cas d'usage : "Si vous aimez l'Audi Q7, vous aimerez..."

GraphRAG : Approche NL2SPARQL

Du Langage Naturel à la Requête Formelle

Cette première approche utilise le LLM comme un traducteur sémantique strict vers le langage de requête du graphe.

Pipeline :

  1. Réception de la question en langage naturel.
  2. Injection du schéma de l'ontologie dans le contexte du LLM.
  3. Génération de la requête SPARQL syntaxiquement valide.
  4. Exécution sur le graphe et retour des résultats bruts.

Avantage : Réponses factuelles, précises et sans hallucination.

GraphRAG : Approche Embeddings

Recherche Sémantique Vectorielle

Cette approche transforme le graphe en un espace vectoriel, permettant une recherche par similarité plutôt que par correspondance exacte.

Pipeline :

  1. Calcul des embeddings pour chaque nœud (véhicule) à l'avance.
  2. Vectorisation de la question utilisateur en temps réel.
  3. Recherche des K plus proches voisins (Cosine Similarity).
  4. Utilisation des voisins comme contexte pour générer la réponse.

Avantage : Gère le flou sémantique, les synonymes et les questions ouvertes.
